## The question

Which USB connector does the instrument have, what else does that port do besides MIDI, and which USB device stack implements the MIDI class?

## Why it matters

USB is how the instrument reaches a computer. The connector is a hole in the body the mechanical engineers have to place. The stack decides whether a computer recognises the instrument as a MIDI device without a driver, and whether sending a message can ever stall the scan.

## What Tiger Bass 1 did

A Micro-B connector on the microcontroller's full-speed port, with TVS protection and VBUS sensing. In firmware, MIDI packets were sent by calling ST's HID class send function after a busy-wait on the HID state. See [`../legacy/tigerbass1-notes.md`](../legacy/tigerbass1-notes.md).

## Part 1: connector

### A. Micro-B, as before

Known footprint and circuit. The connector is fragile and going out of use.

### B. USB-C

The current standard, reversible, mechanically stronger. As a device it needs a pull-down resistor on each of the two CC pins so that a host supplies power. More pins to solder, and many USB-C receptacles have pads under the body.

### C. Panel-mount connector on a cable to the board

A connector fixed to the body with a short internal cable to a header on the board. The board can sit anywhere, and a yank on the cable loads the body instead of the PCB. Adds a cable and a part.

## Part 2: what the port does

- MIDI only.
- MIDI, and powers the instrument when plugged in.
- MIDI, power, and charges the battery. This ties the decision to [0009](0009-battery-and-power-tree.md).

## Part 3: stack

### A. ST's USB device library with a MIDI class

Generated by CubeMX, so it fits the existing project structure. The class list CubeMX offered last year's team had audio, serial, HID, mass storage and firmware update, and no MIDI class, so one has to be written or adapted. That is what they worked around by using HID calls.

### B. An open-source USB stack with a MIDI device class

For example TinyUSB, which includes a MIDI device class and supports STM32. Less to write. A second body of third-party code to learn, integrate with CubeMX's output, and keep the licence terms for.

### C. Keep last year's approach

It produced notes on a computer. It is not how the class is meant to be used, and its send path blocks.

## How to choose

1. The instrument enumerates as a standard USB MIDI device on the operating systems we care about, with nothing to install (TB2-11).
2. Sending a message never blocks the scan (TB2-01).
3. The connector survives being plugged in and pulled on, on an instrument that gets moved around.
4. The team can solder the connector.
5. How much new firmware has to be written and understood.

## What we need to find out first

1. **What exactly last year's firmware did** to make a HID-class call deliver MIDI. Prompt 2, once the firmware is in `legacy/`.
2. **Which operating systems** the sponsor uses.
3. **USB vendor and product IDs.** A device needs a pair. Find out what LSU or the sponsor expects for a prototype.
4. **Whether charging over this port is wanted**, from [0009](0009-battery-and-power-tree.md).
